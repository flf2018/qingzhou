# 轻舟

独立运行的 Windows 桌面代理客户端，已内置 Xray 和 sing-box，不需要启动其他代理程序。

## 使用

推荐安装 `release/QingZhou-0.6.1-Setup.exe`，可选择安装位置，并创建桌面和开始菜单快捷方式。安装完成后，从快捷方式打开「轻舟」。

不想安装时，下载 `release/QingZhou-0.6.1-win-x64.zip`，完整解压到一个固定文件夹，再运行其中的 `QingZhou.exe`。不要直接在压缩包内运行，也不要单独移动 EXE；同目录的 resources 等文件必须保留。

两种版本都只在安装或手动解压时展开文件，日常启动不再重复自解压。沿用原来的用户数据目录，已有节点会保留。卸载默认保留用户数据。窗口显示后再检查管理员权限，开启 TUN 时会等待检查结果。

通知区提供「轻舟」托盘图标，单击或双击可恢复窗口，右键菜单可打开窗口、隐藏到托盘、断开连接或退出。点击窗口右上角 × 会隐藏到托盘，连接继续保持；选择托盘菜单「退出轻舟」才会断开连接、恢复系统代理并结束程序。Windows 可能将图标折叠在通知区的上箭头中。

进入应用后点击「导入节点」，粘贴节点链接或订阅地址，选择节点后点击「连接」。

节点页提供「智能分流 / 全局代理」。默认智能分流，国内域名和国内 IP 直连，其余公网流量走所选节点；全局代理让公网流量走节点。两种模式均保留本地、内网和私有地址直连，并支持系统代理与 TUN。切换时先断开当前连接，重新连接后生效，选择会保存。

连接后主进程每分钟检测一次代理通路，连续两次失败时重新连接当前节点，重试至少间隔三分钟；休眠唤醒或解锁后五秒检查。检测通过专用本地端口强制经过节点，TUN 模式还检查系统路由与 DNS 的实际联网情况；重连时重新读取物理网卡。手动断开、切换分流模式或关闭 TUN 会取消恢复，日志记录检测失败和恢复结果。

TUN 检测使用固定公网 IP 的 HTTPS 请求，强制经过 TUN、SOCKS 桥和节点，避免系统 DNS 将检测域名解析到直连地址而误判正常。节点/TUN 意外退出后保留恢复会话，自动重连失败也保留 TUN 开关偏好并继续重试。连接面板区分联网正常、检测中、通路异常和自动重连；具体检测时间和错误保存在用户数据目录的 `connection-health.jsonl`，单文件最多约 1 MiB，保留一份滚动备份，不保存节点配置或原始内核输出。该检测仅代表检测目标的可达性。

分流使用随应用打包的离线国内域名/IP 规则，同时按流向选择 DNS；列表来自内置 Xray 发布资源中的 Loyalsoldier 数据集。规则来源、输入摘要及许可证见 `vendor/routing/`。它们是打包时快照，不会自动在线更新；更新已验证的内核数据文件后，运行 `npm run build:routing` 可重新生成。应用启动节点时按所选模式生成运行配置：完整 JSON 中原有的路由和 DNS 策略会被应用策略替换，节点协议、认证和传输参数保留，原始导入文件不修改。

支持 VLESS、VMess、Trojan、Shadowsocks、Hysteria2、TUIC 常见链接，以及明文/Base64 节点列表订阅和完整 Xray/sing-box JSON。高级参数、插件和 Clash YAML 不保证兼容，不支持的链接可改用完整 JSON。

默认连接后设置 Windows HTTP/HTTPS 系统代理，断开或正常退出时恢复之前的代理与 PAC。下次启动会尝试恢复上次异常退出留下的设置；其他应用已改动代理时，不覆盖其新设置。系统代理只影响遵循该设置的应用，不等同于 TUN 全局接管。

需要接管不遵循系统代理的应用时，在「代理节点 → TUN 全局接管」开启 TUN（切换模式时会先断开当前连接），接受 Windows 管理员授权。应用重启后选择节点并点击连接。取消授权会回退设置；正常启动仍不要求管理员权限。再次打开非管理员实例时，连接 TUN 会再次请求授权。

TUN 接管 IPv4/IPv6 的 TCP、UDP 与 DNS，局域网直连；UDP 转发取决于所选节点。连接期间暂停自动系统代理，保留其开关偏好。使用内置 sing-box 创建虚拟网卡，经带随机认证的本地 SOCKS 桥接现有 Xray/sing-box 节点，原始节点配置不变。精确匹配节点内核进程路径直连，并绑定物理默认接口，避免流量回环。国外 DNS 使用经当前节点发送的 Cloudflare DoH，智能分流的国内域名使用直连 DNS；节点服务器域名通过开启前读取的物理网卡 DNS 解析，以避免启动循环依赖。

正常停止使用独立的 Windows 监督进程发送 Ctrl+C，使内核释放虚拟网卡、路由、DNS 和 WFP 会话；桌面进程意外退出时，监督进程检测 stdin EOF 后执行同样清理。监督进程本身被终止时，Windows Job Object 会结束其子进程。系统断电、内核驱动异常及与其他 VPN 的冲突不在普通进程退出测试的保证范围内。导入的配置已带 TUN 入站时，应用会拒绝叠加第二套 TUN。

从链接生成的配置使用 HTTP `127.0.0.1:10808`；Xray 同时提供 SOCKS `127.0.0.1:10809`，sing-box 的 10808 为 mixed 端口。其他代理程序占用相同端口时，需要先停止它们。

默认窗口为 1080×720，最小为 960×640，可拖动调整大小。

节点卡片的「测延迟」通过该节点请求 Google HTTPS 204 服务，显示 HTTP 延迟（包含建立连接和 TLS 的时间）。选择节点后点击「开始测速」，依次检测延迟、下载和上传速度，单位为 Mbps；使用 Cloudflare 测试服务，一次最多约 12 MiB 数据加协议开销。结果仅保留在本次会话，可取消检测，失败会显示原因。测速使用独立临时代理端口，不开启系统代理或 TUN；结束后停止临时内核并删除临时配置。结果代表节点到测试服务的表现。

测速测试覆盖真实双内核转发、取消、流量限制、HTTPS CONNECT 和证书验证。本地 TLS 测试私钥仅用于测试；测试 CA 只传入子进程，不修改系统信任。

## 开发与打包

需要 Node.js 22.12+、Windows PowerShell 和 Windows 自带的 .NET Framework 4.x 编译器（仅用于构建小型监督程序，不需要安装 .NET SDK）：

```powershell
cd D:\github\v2rayN\electron-client
npm ci
npm run download:cores
npm run desktop
```

- `npm run dev`：浏览器界面预览；本地文件、订阅、内核和系统代理操作仅在桌面程序可用。
- `npm run dist:win`：生成 Windows x64 安装版 EXE 和 ZIP 解压版，均包含运行环境、两个内核及相关资源。
- `npm run dist:portable`：按需生成旧式单文件便携 EXE；此形式每次启动仍需解压，日常使用推荐安装版或 ZIP 版。
- `npm run pack:win`：生成 `release/win-unpacked/`；其中 EXE 必须与同目录依赖一起分发。
- `npm run build:native`：从 `native/TunHost.cs` 构建 `build/TunHost.exe`；桌面启动和打包命令自动执行。首次运行测试前也应执行一次。
- `npm run build:routing`：从已内置的 geo 数据生成离线国内规则，桌面启动和打包命令自动执行。
- `npm run test:zip`：完整解压发布 ZIP 并运行其中的应用，检查资源、名称、路由开关和双内核实际本地转发。
- `npm test`：配置、订阅、子进程、系统代理恢复测试；在 Windows 上用两个真实内核校验六种链接生成的配置，并测试 TUN 配置、真实 SOCKS TCP/UDP 桥接、监督进程的 Ctrl+C/EOF/崩溃清理。
- `npm run test:desktop`：隔离数据目录验证界面、IPC、品牌文案、TUN 失败回退，以及权限检查未完成时窗口已显示且 TUN 操作会等待。
- `npm run test:exe`：直接运行发布 EXE，分别启动内置 Xray 和 sing-box，完成真实本地 HTTP 转发后停止；同时验证重要文本的对比度并输出截图。测试关闭自动系统代理，不改动当前用户的 Internet Settings；调试端口仅测试时启用。

内核固定版本、官方发布地址、SHA256 和许可证地址保存在 `vendor/cores/manifest.json`，下载时验证摘要。内核源代码分别位于 https://github.com/XTLS/Xray-core/tree/v26.3.27 和 https://github.com/SagerNet/sing-box/tree/v1.14.3 。许可证随内核保留。当前 EXE 未签名。

## 界面与图标

应用名称为「轻舟」，界面参考 macOS，采用浅灰侧栏、白色分组面板与蓝色操作控件；连接状态置顶，代理模式与 TUN 集中排列，节点列表优先展示，不显示开发框架标识。页面主题在 `src/theme.css`。原始生成图标、尺寸转换结果和完整提示词见 `build/icon-prompt.md`；页面使用 `src/assets/chenglian.png`，窗口使用 `build/chenglian.png`，EXE 使用 `build/icon.ico`。

## 当前范围

已实现内置双内核、节点/订阅/JSON 导入、节点筛选、连接启停、监听端口检测、自动系统代理及恢复、TUN 开关、智能分流/全局代理、通知区托盘、管理员重启、HTTP 延迟、下载/上传测速、日志和本地保存。

尚未提供自定义路由编辑、自启动、订阅分组及定时增量更新和自动更新。连接就绪表示本地代理已监听，TUN 就绪表示接管内核已启动；远程线路的可用性仍取决于节点与网络。自动测试未使用用户的远程节点凭据验证外网，也未执行管理员 UAC 或改变宿主机的全局路由/DNS；真实虚拟网卡接管需在授权后的 Windows 实机连接中确认。

配置以明文存放在独立用户数据目录的 `profiles.json`、`active-config.json` 和 `tun-config.json`，恢复记录为 `system-proxy-backup.json`，TUN 输出为 `tun.log`（每次连接重置）；日志可能包含敏感信息。仅有 SOCKS 入站或要求认证的 HTTP 入站不能直接用于 Windows 系统代理，可以使用 TUN 模式，或关闭自动系统代理。

页面不直接访问 Node.js；主进程通过固定 IPC 操作处理配置与代理，并启用上下文隔离和沙箱。自定义 JSON 中的 TUN、文件和入站仍由内核执行，请只使用可信配置。

旧版 mKCP 配置中的 header/seed 会在启动时转换为内置内核对应的 FinalMask 格式，保持伪装和认证参数，原始导入配置保持不变。启动前会先运行内核配置检查。测试覆盖旧版服务端与新客户端的实际本地 mKCP 转发；旧测试内核位于忽略目录 .cache/cores/xray-25.12.8，不随应用分发。
